# ADR 0001: v0.6.0 Breaking API Consolidation (Layers, Semantic Selectors, Status Vocabulary & Prefix Policy)

- **Status**: Accepted
- **Date**: 2026-11-05
- **Epic**: [#210](https://github.com/kidthales/picotol/issues/210)
- **Sub-Issues**: [#205](https://github.com/kidthales/picotol/issues/205), [#206](https://github.com/kidthales/picotol/issues/206), [#207](https://github.com/kidthales/picotol/issues/207), [#208](https://github.com/kidthales/picotol/issues/208), [#209](https://github.com/kidthales/picotol/issues/209), [#214](https://github.com/kidthales/picotol/issues/214), [#215](https://github.com/kidthales/picotol/issues/215)

## Context & Problem Statement

The 2026-11-02 clean-room audit identified four classes of downstream consumer friction in `@kidthales/picotol` `v0.5.x`, alongside one scheduled token retirement from `v0.5.1`:

1. **Cascade Layer Name Collisions (`C3`)**:
   `src/` declares generic top-level cascade layer names (`@layer tokens, reset, base, components, utilities;`). These collide directly with Tailwind CSS (`@layer base, components, utilities;`) and common host application layer taxonomies whenever `dist/picotol.css` or `dist/picotol.core.css` is imported alongside another layered stylesheet.
2. **Hijacked Semantic Elements & ARIA Live Regions (`C4`)**:
   In `src/components.css`, bare `aside:not(nav *)` and bare `[role="alert"]` are styled as callout banners, and bare `[role="status"]` is styled as an inline pill badge. Consumers using `<aside>` for page sidebars or `role="status"` / `role="alert"` for screen-reader live regions, form error summaries, or toast containers receive unintended borders, padding, and pill backgrounds.
3. **Drifting Status Vocabularies & Competing Dot Primitives (`C8`)**:
   Three dot primitives (`.pt-dot`, `.pt-status-dot`, `.status-dot`) and two competing status vocabularies (`ok | info | warning | critical` in `--pt-status-*` tokens versus `success | danger | valid | invalid` across component classes) have drifted in selector shape, default background color, and `forced-colors` treatment.
4. **Unprefixed Generic Classes & Custom Properties (`C8`, `C15`, `B3`)**:
   Approximately 30 unprefixed generic classes (`.badge`, `.toast`, `.active`, `.small`, `.sm`, `.show`, `.close`, `.fill`, `.end`, `.label`, `.value`, `.card`, `.dropdown`, etc.) and the unprefixed custom property hook `--marker-pos` collide with Bootstrap, utility libraries, and host application stylesheets.
5. **Surprising Default Flex Column `body` Layout (`C5`)**:
   `@layer reset` in `src/base.css` applies `display: flex; flex-direction: column; min-height: 100dvh;` to bare `body`. For a drop-in semantic stylesheet, turning `body` into a flex container disables vertical margin collapsing and converts every direct child of `body` into a flex item.
6. **Scheduled Removal of `v0.5.1` Derived Density Aliases (`C1` / `#203`)**:
   Issue [#203](https://github.com/kidthales/picotol/issues/203) refactored components in `v0.5.1` to late-bind `--pt-form-y` and `--pt-form-x`, retaining `:root` declarations for `--pt-form-element-spacing-vertical`, `--pt-form-element-spacing-horizontal`, and `--pt-btn-padding-block` marked `/* @deprecated: removed in v0.6.0 */` for one minor release.
7. **Static Linter Reachability Constraint**:
   `tools/lint.mjs` operates strictly on `@kidthales/picotol`'s own `src/`, `dist/`, and `README.md` during repository CI. Because `@kidthales/picotol` ships as a pure-CSS package with zero runtime JavaScript or consumer CLI plugin, `tools/lint.mjs` cannot inspect consumer HTML/CSS or emit build-time deprecation diagnostics in downstream projects.

---

## Architectural Parti

**One namespace, one status vocabulary, one dot primitive, and zero surprising layout or landmark defaults.**

All breaking changes are consolidated into `v0.6.0` with a written migration path ([`docs/migrate-0.6.md`](../migrate-0.6.md)). Except for cascade layer namespacing (which cannot be aliased in CSS without duplicating every rule block) and the `body.pt-app` layout opt-in, deprecated selectors remain functional in `v0.6.0`—either quarantined in `@layer picotol.legacy` or retained as `/* @deprecated: removed in v0.7.0 */` aliases—for exactly **one minor release** before removal in `v0.7.0`.

## Decisions

### 1. Cascade Layer Namespacing (`#206` — Hard Break, No Alias)

- Rename all cascade layers in `src/` and across all distribution bundles (`dist/picotol.core*.css`, `dist/picotol*.css`, `dist/picotol.layer*.css`) under the `picotol.*` namespace:
  ```css
  @layer picotol.legacy, picotol.tokens, picotol.reset, picotol.base, picotol.components, picotol.utilities;
  ```
- Because CSS Cascading and Inheritance Level 5 treats `@layer picotol.tokens` as a sublayer of `@layer picotol`, consumers can still order the entire framework with a single `@layer reset, picotol, app;` statement or target individual sublayers (`@layer picotol.components`).
- `dist/picotol.layer.css` and `dist/picotol.css` emit the identical `@layer picotol.*` output; the `@kidthales/picotol/layer` package export is retained so existing `@import "@kidthales/picotol/layer"` statements continue to resolve cleanly without double-nesting (`picotol.picotol.*`).
- **No Alias**: CSS `@layer` names cannot be aliased without duplicating rule bodies. Renaming `tokens/reset/base/components/utilities` to `picotol.*` is an intentional **hard break** in `v0.6.0`.

### 2. Class-Gating Bare Semantic Selectors via `@layer picotol.legacy` (`#207`)

- In `@layer picotol.components`, callout and badge styling strictly requires explicit classes (`.pt-callout`, `.pt-badge`, `.pt-indicator`).
- Bare semantic and ARIA live-region selectors—`aside:not(nav *)`, `[role="alert"]`, and `[role="status"]`—are removed from `@layer picotol.components` and placed in `@layer picotol.legacy`, annotated with `/* @deprecated: removed in v0.7.0 */`.
- `@layer picotol.legacy` is declared **first** in the cascade layer order (lowest cascade priority). Any rule in `picotol.base`, `picotol.components`, `picotol.utilities`, or any consumer layer declared after `picotol.legacy` overrides these legacy rules without specificity escalation.
- `@layer picotol.legacy` and its bare-element selectors will be removed in `v0.7.0`.

### 3. Canonical Status Vocabulary & Single `.pt-dot` Primitive (`#208`)

- **Canonical Status Vocabulary**: Standardize on `ok | info | warning | critical`, matching the `--pt-status-{ok,info,warning,critical}-{fg,border,bg}` custom property triads.
- **Single Dot Primitive**: `.pt-dot` is the sole canonical status dot primitive, paired with BEM modifiers:
  - `.pt-dot--ok`
  - `.pt-dot--info`
  - `.pt-dot--warning`
  - `.pt-dot--critical`
  - `.pt-dot--pulse`
- **Status-Bearing Components**: `.pt-badge`, `.pt-indicator`, `.pt-chip`, `.pt-callout`, `.pt-progress`, `.pt-meter-range`, and `.pt-meter-mark` support `[data-status="ok|info|warning|critical"]` alongside `pt-`-prefixed status modifiers (`.pt-ok`, `.pt-info`, `.pt-warning`, `.pt-critical`, `.pt-callout-{ok,info,warning,critical}`, `.pt-progress-{ok,info,warning,critical}`).
- **Deprecated Aliases (Removed in `v0.7.0`)**:
  - Dot aliases: `.pt-dot--success`, `.pt-dot--danger`, `.status-dot`, `.pt-status-dot`, `.pt-status-dot-ok`, `.pt-status-dot-success`, `.pt-status-dot-warning`, `.pt-status-dot-critical`, `.pt-status-dot-danger`, `.pt-status-dot-info`, and unprefixed child modifiers (`.pulse`, `.pt-pulse`).
  - Vocabulary aliases: `success`, `danger`, `valid`, `invalid` class/attribute variants (`.pt-callout-success`, `.pt-progress-success`, `.pt-progress-danger`, `[data-status="success|danger|valid|invalid"]`) and unprefixed status classes (`.ok`, `.info`, `.warning`, `.critical`, `.success`, `.danger`, `.valid`, `.invalid`).
  - All deprecated status and dot selectors remain in `v0.6.0` marked `/* @deprecated: removed in v0.7.0 */`.

### 4. `pt-` Prefix Policy for Public Classes & Custom Properties (`#214`)

- All canonical public class selectors in `src/` must use the `pt-` prefix, and all canonical custom properties must use `--pt-` or `--tol-`.
- Every unprefixed public class in `src/` (including `.badge`, `.toast`, `.active`, `.small`, `.sm`, `.show`, `.close`, `.fill`, `.end`, `.label`, `.value`, `.card`, `.dropdown`, `.segmented`, `.sheet`, `.skeleton`, etc.) receives a canonical `pt-`-prefixed counterpart in `v0.6.0`. Unprefixed class names remain as `/* @deprecated: removed in v0.7.0 */` aliases for one minor release and are guarded by an explicit allowlist in `tools/lint.mjs`.
- The unprefixed custom property hook `--marker-pos` is superseded by canonical `--pt-marker-pos`, with `--marker-pos` retained as a fallback read until `v0.7.0`.

### 5. Opt-In Flex Column `body` Layout (`#215`)

- Bare `body` in `@layer picotol.reset` retains `margin: 0` with standard block flow (`display: block`).
- The full-viewport sticky-footer flex column layout (`min-height: 100dvh; display: flex; flex-direction: column;` with `& > :where(main, [role="main"]) { flex: 1 0 auto; }`) becomes opt-in via `body.pt-app`.

### 6. Removal of `v0.5.1` Deprecated Derived Density Aliases (`#209`)

- Completing the one-minor-release deprecation cycle started in `v0.5.1` ([#203](https://github.com/kidthales/picotol/issues/203)), remove the `:root` declarations for `--pt-form-element-spacing-vertical`, `--pt-form-element-spacing-horizontal`, and `--pt-btn-padding-block` in `v0.6.0`.
- Consumers customize control spacing via `--pt-form-y` and `--pt-form-x` (globally or within scoped density containers).

### 7. Deprecation Communication Policy & Removal Schedule

Because `tools/lint.mjs` only lints `@kidthales/picotol`'s own source tree and cannot reach downstream consumer codebases, every deprecation in `@kidthales/picotol` **must** be communicated through three consumer-visible channels:

1. **`CHANGELOG.md`**: Listed explicitly under `### Deprecated` (when deprecated) and `### Removed` / `### Changed` (when removed).
2. **Migration Guide ([`docs/migrate-0.6.md`](../migrate-0.6.md))**: Provides before/after markup diffs and 1:1 selector/token mapping tables.
3. **`/* @deprecated: removed in v0.7.0 */` Comments**: Attached directly to deprecated selectors and custom properties in `src/*.css` and preserved in unminified `dist/picotol*.css` bundles so developers inspecting source or DevTools rules see the deprecation notice and target removal version.

Internally, `tests/doc-lint.test.mjs` enforces that `README.md`, the current `CHANGELOG.md` release section, and current release notes reference only canonical `v0.6.0` selectors and tokens.

## Consequences

- **Positive**:
  - Zero cascade layer collisions with Tailwind CSS (`@layer base, components, utilities`) or host stylesheets.
  - Semantic `<aside>`, `role="status"`, and `role="alert"` elements are no longer hijacked when used for application layout or assistive live regions, while existing classless consumers have a one-minor-release buffer via `@layer picotol.legacy`.
  - Complete 1:1 alignment between `--pt-status-{ok,info,warning,critical}-*` tokens, `[data-status]` attributes, `.pt-dot--*` modifiers, and component status classes.
  - Every public class and custom property is namespaced under `pt-` / `--pt-` / `--tol-`, eliminating class collisions with Bootstrap and application CSS.
- **Trade-offs & Mitigation**:
  - Retaining `v0.6.0` deprecated selector aliases temporarily adds selector bytes, raising the minified bundle budget ceiling from 40 KB to 44 KB (expanded 52 KB $\to$ 56 KB, unpacked size 350 KB $\to$ 380 KB) until `v0.7.0` deletes them; selector grouping (`:is(...)` / `:where(...)`) keeps the byte overhead minimal.
  - Consumers relying on bare `@layer tokens` or default `body` flex column layout must update their layer declarations and add `<body class="pt-app">` when upgrading to `v0.6.0`, guided by [`docs/migrate-0.6.md`](../migrate-0.6.md).
